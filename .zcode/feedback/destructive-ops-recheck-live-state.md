# destructive-ops-recheck-live-state

- 日期: 2026-08-13
- 来源: 家族脚手架跨仓实践（三起真实事故汇总：误删在跑会话/被拒调用重发出双进程/性能猜因被实测推翻）
- 信号: 对远端/生产执行删除、重启、重跑前；被拒/超时的远程调用想重发；凭直觉给性能优化建议
- occurrence: 3（毕业：已进宪法纪律 8 + hook 危险命令拦截）

## 现象

拿旧快照/时间推断当远端当前状态，误删正在运行的工作；被拒绝的调用重发导致双进程并发写；未实测（EXPLAIN/采样/计时）就推荐性能方案，方向全错。

## 根因

远端状态是移动靶；分布式调用的「失败」可能是「对端已执行」；性能根因反直觉。

## 规则

远端/生产任何写操作前当场实查**当前**实况；被拒/中断/超时的远程调用一律按「可能已执行」对待，先实查对端结果再决定重发；性能根因先实测再荐方案。

## 执法建议

已机制化：hook 危险命令拦截（rm-rf-root/git-reset-hard/broad-kill 等 exit 2）+ gate-log 留痕；Fast Mode 不豁免。
